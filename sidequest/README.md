# ⚡ UCU SideQuest

**UCU SideQuest** — це повнофункціональний веб-додаток для спільноти Українського Католицького Університету (УКУ), створений для пошуку однодумців для спонтанних активностей, дослідження університетських подій та змістовної підготовки до них.

Проєкт відповідає на 3 ключові питання студента:
1. **Що цікавого відбувається?** — централізована стрічка університетських подій та студентських ініціатив.
2. **З ким я можу піти?** — спонтанні SideQuests (кава, настільний теніс, прогулянки Стрийським парком, спільне розв'язання дедлайнів).
3. **Чому ця подія корисна та як підготуватися?** — структуровані розділи «Чому варто відвідати?», рекомендації щодо підготовки та профілі спікерів із посиланнями.

## 🏛️ Архітектура проєкту

Монорепозиторій містить чітко розділені компоненти:

```
sidequest/
├── backend/                  # FastAPI (Python 3.13), async SQLAlchemy 2, Pydantic v2
│   ├── alembic/              # Міграції бази даних
│   ├── app/
│   │   ├── api/v1/           # Версіоновані маршрути API (/auth, /me, /sidequests, /events, /organizations)
│   │   ├── models/           # SQLAlchemy 2 моделі таблиць
│   │   ├── schemas/          # Pydantic v2 схеми валідації запитів та відповідей
│   │   ├── repositories/     # Рівень доступу до даних (Repository Pattern)
│   │   ├── services/         # Бізнес-логіка, перевірка лімітів та прав доступу
│   │   └── utils/            # Безпека (bcrypt, JWT)
│   ├── tests/                # Pytest набір інтеграційних та e2e тестів
│   ├── seed.py               # Ідемпотентний скрипт наповнення демонстраційними даними
│   ├── requirements.txt      # Залежності Python

├── frontend/                 # Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS
│   ├── app/                  # Сторінки та макети (App Router)
│   ├── components/           # UI компоненти (карточки, навігація, фільтри)
│   ├── features/auth/        # Клієнтська автентифікація та контекст користувача
│   ├── lib/                  # Централізований типізований API-клієнт та утиліти

├── .env.example              # Безпечний приклад конфігурації оточення
└── README.md
```

## 🚀 Швидкий запуск

### Варіант 1: Через Docker Compose (PostgreSQL + Backend + Frontend)

Запуск усього стеку однією командою:

```bash
docker compose up --build
```

Ця команда:
1. Запустить контейнер PostgreSQL 16 із постійним томом даних (`pgdata`).
2. Запустить міграції Alembic (`alembic upgrade head`).
3. Завантажить демонстраційні дані (`python seed.py`).
4. Запустить FastAPI бекенд на порту `8000`.
5. Збере та запустить Next.js фронтенд на порту `3000`.

Додаток доступний:
- **Веб-інтерфейс**: [http://localhost:3000](http://localhost:3000)
- **API Документація (Swagger UI)**: [http://localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs)
- **Альтернативна документація (ReDoc)**: [http://localhost:8000/api/v1/redoc](http://localhost:8000/api/v1/redoc)

---

### Варіант 2: Локальний запуск для розробки (без Docker)

Якщо Docker Desktop вимкнено або потрібна швидка розробка:

#### 1. Бекенд

```bash
cd sidequest/backend

# Створення та активація віртуального середовища
python -m venv venv
# Windows:
.\venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Встановлення залежностей
pip install -r requirements.txt

# Налаштування БД (за замовчуванням SQLite для автономної розробки або PostgreSQL):
# Для SQLite:
$env:DATABASE_URL="sqlite+aiosqlite:///./sidequest.db"   # PowerShell
# export DATABASE_URL="sqlite+aiosqlite:///./sidequest.db" # Linux/macOS

# Запуск міграцій та наповнення демо-даними:
alembic upgrade head
python seed.py

# Запуск сервера API
uvicorn app.main:app --reload --port 8000
```

#### 2. Фронтенд

У новому терміналі:

```bash
cd sidequest/frontend

# Встановлення залежностей
npm install

# Запуск dev-сервера
npm run dev
```

Фронтенд буде доступний за адресою [http://localhost:3000](http://localhost:3000).

Для зручності демонстрації на сторінці входу додано **кнопки швидкого входу в 1 клік**, а також доступні наступні тестові облікові записи:

| Роль | Email | Пароль | Можливості |
|---|---|---|---|
| 🎓 **Студент** | `student@ucu.edu.ua` | `StudentPass123!` | Створення SideQuests, приєднання/вихід, перегляд учасників, перегляд подій |
| 🏛️ **Організатор** | `organizer@ucu.edu.ua` | `OrganizerPass123!` | Створення та редагування подій УКУ, додавання спікерів, посилань та матеріалів підготовки |
| 🛡️ **Адміністратор** | `admin@ucu.edu.ua` | `AdminPass123!` | Повні права модерації, керування ролями, скасування активностей |

> *Примітка: Демо-паролі використовуються виключно для локальної демонстрації та захешовані алгоритмом bcrypt.*

## 🧪 Тестування та перевірка

Проєкт містить повний набір інтеграційних та end-to-end тестів на бекенді, що перевіряють бізнес-правила:

```bash
cd sidequest/backend
.\venv\Scripts\pytest.exe -v
```

Тестовий набір перевіряє:
1. **Реєстрацію та автентифікацію**: валідація формату, хешування паролів, заборона дублікатів email, захист `/me` за JWT.
2. **Бізнес-правила SideQuests**:
   - Заборона планування активності в минулому (з урахуванням часового поясу `Europe/Kyiv`).
   - Заборона часу завершення раніше за час початку.
   - **Атомарний контроль ліміту місткості**: неможливість перевищити ліміт учасників.
   - **Заборона повторного приєднання**: один користувач не може приєднатися двічі (перевірка у БД через `UniqueConstraint`).
   - **Права доступу**: редагувати або скасовувати SideQuest може лише автор або адмін.
   - **Скасовані активності**: скасований SideQuest переходить у статус `canceled` і не приймає нових учасників.
3. **Бізнес-правила подій**:
   - Студент не має прав створювати офіційні події (перевірка `403 Forbidden`).
   - Організатор створює подію зі спікерами та матеріалами підготовки.
   - Відсутність опціональних полів (спікери, «Чому варто піти») не ламає відображення.
   - Реєстрація участі у події та скасування участі.
4. **End-to-End сценарій**: студент реєструється, знаходить SideQuest через пошук, переглядає деталі, приєднується, перевіряє розділ «Мої активності», а згодом скасовує участь.

Перевірка збірки фронтенду:
```bash
cd sidequest/frontend
npm run build
```
*(Усі 10 маршрутів App Router успішно компілюються у статичні/динамічні сторінки без помилок типів).*

## 🔒 Безпека та бізнес-правила

- **Паролі**: хешуються за допомогою `bcrypt`. Паролі ніколи не зберігаються у відкритому вигляді.
- **Автентифікація**: JWT токени (HS256) із захистом маршрутів через `OAuth2PasswordBearer`.
- **RBAC**: розмежування ролей (`student`, `organizer`, `admin`) забезпечується на рівні бекенду. Публічна реєстрація не дозволяє призначити собі роль `admin`.
- **Приватність**: налаштування видимості (`public`, `campus_only`, `hidden`). Приватні учасники відображаються як «Анонімний учасник» для захисту персональних даних.
- **SQL Injection**: захист через SQLAlchemy 2 ORM та параметризовані запити.
- **XSS**: автоматичне екранування в Next.js/React.
- **CORS**: обмежено дозволеними джерелами (`localhost:3000`).

## ☁️ Цільова хмарна архітектура AWS (Production Target)

Для промислового розгортання в середовищі AWS передбачена наступна цільова архітектура:

1. **Автентифікація**: **Amazon Cognito User Pools**. Бекенд спроєктовано з ізоляцією провайдера автентифікації — заміна локальної JWT-валідації на Cognito JWKS виконується без зміни API-контрактів.
2. **Бекенд**: **AWS Lambda** (із адаптером `Mangum`) за **Amazon API Gateway** (серверлес-архітектура без потреби тримати постійний сервер).
3. **Фронтенд**: статичний Next.js білд на **Amazon S3** з глобальною роздачею через **Amazon CloudFront** CDN.
4. **База даних**: **Amazon Aurora Serverless v2 (PostgreSQL)** із автоматичним масштабуванням ACU та підтримкою VPC-з'єднань.
5. **CI/CD**: **GitHub Actions** (автоматичний запуск `pytest`, `next build`, лінтинг та деплой у AWS).
6. **Спостережуваність**: **Amazon CloudWatch Logs & Metrics**.

## ⚠️ Відомі обмеження та особливості оточення

- **Docker Desktop**: якщо локальний демон Docker Desktop не запущено у вашій Windows-системі, скористайтеся **Варіантом 2 (Локальний запуск)**. Завдяки модульній конфігурації бекенд підтримує як PostgreSQL, так і локальний SQLite без зміни коду.
- **Часовий пояс**: усі дати зберігаються з часовим поясом UTC та відображаються у зоні `Europe/Kyiv`.
